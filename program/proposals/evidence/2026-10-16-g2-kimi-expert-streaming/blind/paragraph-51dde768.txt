A study asks how well the expert-cache behaviour of a one-trillion-parameter mixture-of-experts model (384 routed experts per layer, eight selected per token plus one shared expert, 60 routed layers) can be predicted for SSD streaming on a 128 GB unified-memory laptop without running anything on the laptop. On a server it records which experts are selected for every token and layer. The routing comes from the about-2.6-bit file a laptop would stream, generating its own responses in four kinds of session: chat, coding, multi-turn tool use replayed from recorded trajectories, and question answering over 8K-16K-token documents, with up to 2,048 decoded tokens each. It replays these selections event by event, so that one token's eight experts at one layer form one cache event, through several policies: least-recently-used, least-frequently-used, a frequency-pinned set chosen on held-out sessions, an offline optimum, and the exact eviction policy of a published laptop streaming engine (per-expert selection counts halved every 16 decoded tokens, lowest count evicted, ties broken by recency). It feeds the per-layer misses into a time model with three storage tiers, because that engine reads experts with ordinary buffered file reads: the engine's own expert cache, the operating system's file cache (capacity bounded by the free memory logged for each published run) and the SSD. The model includes cold starts and the engine's two prefill paths, whole-layer reads and selected-expert reads. Exactly one constant is fitted: the SSD read rate, taken from a single published measurement whose cost does not depend on the prompt, a short append that read the whole expert pool. Everything else is fixed in advance. The model is then tested against eleven held-out published decode speeds of two other models on the target laptop. It is also tested on three within-run contrasts that change only cache state or the code path, with identical routing, so the shared calibration error cancels. It must beat a frozen baseline that derives hit rates from cache size alone. Only if it passes does the study predict the large model's laptop decode speed, as a ratio to an already-measured model on the same sessions, and use that ratio to decide whether compressing the large model for laptop use is worth pursuing.
