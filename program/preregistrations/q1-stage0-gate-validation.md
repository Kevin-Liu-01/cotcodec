# Preregistration: q1-stage0-gate-validation

Status: DRAFT for the program owner's review. Not frozen. Written 2026-10-07
on branch `stage0/q1-core` before any Stage 0 substrate, mutant or control has
been scored on a GPU. Freezing is the program owner's step
(`scripts/preregister.py freeze q1-stage0-gate-validation ...`); a material
change after freezing is a new experiment id.

## 1. Question and claim boundary

Question Q1 (`program/questions/q1-kernel-gate-strength.md`), Stage 0: build
three kernel correctness gates of increasing strength and an independent audit
that no gate sees, and measure, on compiler-generated and pre-2025
human-written Triton kernels and their deterministic mutants, (i) how often
each gate accepts a kernel the audit rejects, (ii) how often each gate rejects
a correct kernel, and (iii) what each gate costs.

Claim boundary: Stage 0 validates the instrument. Mutants are not policy
faults, so no Stage 0 number answers whether a stronger gate changes what RL
learns, and the false-accept share (FA-share) is computed but not interpreted.
Stage 0 runs no model-written kernel on a GPU (decisions D3, D7).

Corpus (built by the substrate and mutator owners against the shared schema):

- **S1**: TorchInductor Triton for every admissible L1/L2 problem, compiled
  with dynamic shapes and normalized to plain `@triton.jit` launches (source
  kind `inductor`). Admission: the b1 launch hook observes at least one launch
  under both autograd modes, and the kernel is correct under the primary audit
  at native shapes.
- **S2**: FlagGems v1.0-manual @18b8e428 (Apache-2.0), Liger-Kernel v0.3.1
  @1520999e (BSD-2-Clause) and Triton tutorials @105cb564 (MIT), adapted with
  recorded normalization diffs. The tutorial matmul keeps default-precision
  `tl.dot` (TF32) and is the TF32-policy control.
- **Mutants**: deterministic rewrites of S1/S2 by the mutator
  (`stage0/q1-mutate`), deduplicated with `TRITON_DISABLE_LINE_INFO=1` at the
  native specialization, capped at 40 per substrate, stratified by family.
- **Controls** (ruling-free): every evaluation problem's reference `Model`
  re-exported as `ModelNew`; KernelBench@423217d9's three adversarial CUDA
  kernels (`result_reuse`, `zero_out`, `non_default_stream`), run verbatim on
  L1/1; hack-emulating mutants (ReLU removal on a ReLU substrate, fabs
  removal, guard-drop tail) from the mutator.

Splits, fixed now:

- **S1 calibration split**: sort the problem ids that have an admitted S1
  substrate, shuffle with Python `random.Random(42).shuffle`, and take the
  first `ceil(n / 2)` as S1-cal. S1-cal is used only for audit calibration
  (section 5.1). S1-eval (the rest) plus all of S2 form the evaluation set.
- **Mutant dev/test split**: sort mutant ids, shuffle with
  `random.Random(42).shuffle`, first half dev (used only to choose c-lite,
  section 4.5), second half test. Every mutant metric is reported on test;
  dev is reported separately and labelled.

## 3. Seeds and units

- Seeds 42, 43 and 44 are full-stack replicates: gate (a)'s `seed_num`, and
  the draw seeds of gate (c) and the audit, shift with the replicate.
  Replicate 42 is primary; 43 and 44 are robustness replicates.
- Draw seeds per channel (`harness/q1/gates/outcome.py::channel_seed`):
  `base + index + 100 * (replicate - 42)` with bases c1 1042, c2 2042,
  c3 3042, A2 4042, A3 5042, A1 6042, A5 7042. Gate (a) derives its five
  trial seeds as KernelBench does (`torch.manual_seed(seed)`, then five
  `torch.randint(0, 2**32 - 1, (1,))`).
- Unit of analysis: the kernel (substrate, mutant or control). Seeds are not
  independent units. Uncertainty for pooled metrics comes from a
  problem-cluster bootstrap (B = 10,000, seed 0); for FRR from exact
  Clopper-Pearson 95% intervals over kernels.

## 4. Gates (frozen)

All gates run with models in training mode, each gate and each audit channel
in its own process (`harness/q1/runner.py`), torch TF32 flags at their process
defaults (matmul TF32 off, cuDNN TF32 on; `tf32_policy = torch-default`).

### 4.1 Gate (a)

- **a (primary)**: KernelBench@44130946 `eval_kernel_against_ref` +
  `run_and_check_correctness` semantics with `num_correct_trials=5`,
  `seed_num=42`, `backend="triton"`: inputs from the problem's `get_inputs()`
  at native shapes, moved to the device without a dtype cast (integer targets
  keep their dtype), the same input objects passed to the reference and then
  to the candidate, output shape check, `torch.allclose(ref, out,
  atol=1e-2, rtol=1e-2)`; all five trials must pass.
- Secondaries: `a_1e-3` (same, tolerance 1e-3), `a_head_1e-4` and
  `a_head_1e-2` (KernelBench@423217d9 semantics: every tensor cast to fp32,
  tolerance 1e-4 or 1e-2), `a_static` (`a` and HEAD
  `validate_kernel_static(code, backend="triton", precision="fp32")`).
- A reference that raises (for example L1/95 under the HEAD fp32 cast) makes
  the item unrefereeable for that variant (verdict `error`, excluded from that
  variant's denominators, always counted and reported).

### 4.2 Gate (b)

- `b1`: a Triton launch is recorded under both `torch.inference_mode()` and
  `torch.enable_grad()` (warm-up 1 outside the hook, 1 hooked step each),
  inputs from `set_seed(42); get_inputs()` without a cast.
- `b2`: in a `torch.profiler` window (CPU and CUDA activities) after 3 warm-up
  and 10 timed calls, holding a 1024-element self-test and 10 calls: decoy if
  the event table has at least one row with positive device time and no row
  matches a captured kernel name (case-insensitive equality or substring
  either way).
- **b (ladder) = a and b1 and b2.** As released, detection errors fail open:
  a `b1` or `b2` row with verdict `error` counts as accept in the ladder and
  is reported separately.
- `b_native`: the unmodified KernelGYM clone's `eval_kernel_against_ref`
  (b0 and b1 and b2), fidelity only.

### 4.3 Gate (c)

**c = b and c1 and c2 and c3**, each family at atol = rtol = 1e-3.

- `c1`: KBV hidden configurations per problem from
  `kbv_hidden_configs.json` (D1 x1.0, D2 x3.0, D3 x0.01, D4 x-1.0 applied to
  floating tensors; L1/90 drops D2; L1/98 drops D4; L1/100 adds D5
  alternating +-1 targets). Deviations from KBV, documented: configuration
  `i` draws after its own seed (section 3); integer tensors keep their dtype.
- `c2`: S-half (leading free root halved), S-double (inner free root doubled,
  reduced to the largest value within 2x native input bytes), S-small (every
  free root divided by 8), each drawn with D1 and D4.
- `c3`: U1 (one free root + 1), U2 (one free root to `(d - d mod 128) + 17`),
  U3 (leading root = 3), and for L1 matmul problems MM1 and MM17 (every free
  root to `(d - d mod 64) + 1` or `+ 17`), each drawn with D1 and D4.
- Free roots are found by static scope analysis (`harness/q1/problems.py`):
  module integer constants reached from `get_inputs` that neither
  `get_init_inputs` nor `class Model` reads; `get_init_inputs()` is checked
  unchanged for every configuration.
- Secondaries from the same outputs: `c_1e-2` (tolerance 1e-2) and
  `c_kbv_raw` (no validity filter; a configuration whose reference raises
  passes, as in KBV).

### 4.4 Validity gate (every c configuration)

A configuration counts only if (i) the fp32 reference output is finite,
(ii) the device fp32 reference is within atol = rtol = 1e-3 of an fp64 replay
of the same model and inputs, and (iii) a CPU fp32 reference is within the
same tolerance of the device reference; integer outputs must match exactly. A
configuration whose reference raises is inadmissible. Inadmissible
configurations are logged; a kernel with no admissible configuration in a
family is unrefereeable in that family (`error`), reported, and excluded from
that family's denominators.

### 4.5 c-lite

If the measured median GPU-seconds of `c` exceed 2x those of `b` per kernel
in the pilot, a reduced configuration set is chosen by greedy set cover on the
dev mutants (maximize newly rejected audit-witnessed dev mutants per
GPU-second; ties by configuration id) and frozen in an addendum
preregistration with a new experiment id before any test mutant is scored.

## 5. Independent audit (frozen at v1 after calibration)

No gate reads audit inputs or verdicts, and the audit reads no gate output.

### 5.1 A1, fp64 oracle (decision D14)

- `e(x) = max_i |x_i - r64_i| / (|r64_i| + 1e-3 * ||r64||_inf)` over
  positions where both are finite; NaN, +Inf and -Inf masks must equal the
  oracle's. The oracle is a deep copy of the reference with parameters,
  buffers and floating inputs in fp64, in training mode.
- Pass if `e(candidate) <= T`, `T = max(M * max(e(r32_device), e(r32_cpu)),
  2^-20)`, `M = 16`.
- **TF32 policy, primary = TF32-admissible**: when the reference dispatches a
  matmul or convolution op, or the candidate source calls `tl.dot`, T is also
  computed from a device reference with matmul and cuDNN TF32 on, and the
  larger T is used. **Secondary = strict-fp32** (device reference with both
  TF32 switches off). Both are always reported.
- Integer and bool outputs: exact match with the oracle under torch's
  first-index tie rule, except at positions where an fp32 reference itself
  disagrees with the oracle (a near-tie certified by the fp64 replay), where
  the candidate may match that fp32 reference.
- Draws: five native `get_inputs()` draws (seeds 6042-6046 at replicate 42).
- Precision-only class: fails A1, every failing draw within 64·T, passes A2,
  A3 and A4. Reported as its own class.
- **Calibration**: on S1-cal only, compute each correct substrate's required
  multiplier `e(candidate) / max(e(r32_device), e(r32_cpu))` over its A1
  draws. If the largest exceeds 16, M is raised once to the smallest power of
  two at least that large. The audit is then frozen as v1 by
  `audit_version_hash` (constants plus SHA-256 of every audit file), before
  any evaluation-split kernel or mutant is scored. Any later change is a new
  audit version, a full rerun, and a disclosed change in every reported number.

### 5.2 A2, held-out values

Seven distributions replace every floating input at native shape: randn,
U[-8, 8], U[0, 1) x 100, spiky (0.1% of entries and the last element along
every axis x1000), ties (U[-4, 4] rounded to 1/8), all-negative, constant
rows. Each draw passes the audit validity gate: the reference runs, its fp32
non-finite masks equal the oracle's, and `max(e(r32_device), e(r32_cpu)) <=
1e-3`. Verdict by the A1 rule.

### 5.3 A3, held-out shapes and refusal classification

From the manifest's A3 configurations (disjoint from every c value of the same
root): `lead1`, `lead5`, `inner37` (largest prime at most 0.37 x native),
`inner137` (smallest prime at least 1.37 x native, within 2x native bytes),
`allprime` (every free root to the largest prime at most 0.37 x native).
Validity as A2. Each draw is classified: pass; silent-wrong (no exception,
fails the A1 rule); crash-after-launch (exception after at least one Triton
launch or aten compute op); refusal-before-launch (exception before any).

### 5.4 A4, tolerance-free contracts

On the first A1 draw and on one randn draw: five-run byte determinism; no
storage shared between the five live outputs; no output sharing storage with
an input; inputs byte-identical after each call; dual poison (outputs
byte-identical when fresh `torch.empty*` allocations are filled with 0x00 and
with 0xFF; on GPU additionally through the `CUDAPluggableAllocator` in
`audit/poison_alloc.c`, run by `audit/gpu_probes.py` in two fresh processes);
`compute-sanitizer --tool memcheck` clean at the smallest A3 configuration (by
input bytes); no watchdog timeout. A4 is the conjunction of the in-process,
poison-allocator and sanitizer rows. A sanitizer run that does not complete
(exit code other than 0 or 86) is reported as `error`, not as a fault.

### 5.5 A5 (secondary tier)

lethe-style EXC-01 (NaN/+-Inf scatter, masks agree), EXC-02 (subnormals),
PRC-01 (fp16, bf16 regimes), PRC-02 (fp16 inputs vs fp32 reference) with
three fixes to lethe's adapter: models stay in training mode (lethe calls
`.eval()`), every floating input is perturbed (lethe perturbs the first), and
the reference shares the candidate's weights.

### 5.6 Contract tiers (decision D14; primary = G)

- **N** = A1 and A2 and A4 at native shapes.
- **G** = N and A3, where refusal-before-launch is "non-general", not a fault.
  This is the primary tier: never silently wrong at held-out shapes.
- **G-strict** = N and A3, refusals count as faults.
- **c-disjoint** = A1 and A4 (channels gate (c) does not share).

All four are always reported under both TF32 policies.

### 5.7 Audit holes

A kernel rejected by a gate on a validity-gated input that the primary audit
accepts is replayed on that input against the fp64 oracle with the frozen T.
Deviation beyond T: an audit hole (audit version bump and full rerun).
Otherwise: a false rejection by that gate.

## 6. Metrics

For each gate g in {a, a_1e-3, a_head_1e-4, a_head_1e-2, a_static, b, c,
c_1e-2, c_kbv_raw, c-lite if adopted}:

- **witnessed mutant**: rejected by the primary audit (tier G,
  TF32-admissible) on some validity-gated input;
- **MS_g** = witnessed mutants rejected by g / witnessed mutants;
  **FAR_g** = 1 - MS_g;
- **FRR_g** = evaluation-set correct substrates rejected by g / evaluation-set
  correct substrates (a "correct substrate" is admitted and accepted by the
  primary audit at replicate 42);
- **audit-hole_g**: count from section 5.7;
- **cost_g**: GPU-seconds per kernel from worker spawn to verdict (compile
  included), median and p95, marginal and amortized; ratios c/b and c-lite/b;
- **FA-share_g** = (accepted by g and audit-rejected) / accepted by g:
  computed, not interpreted (it depends on the mutant mix).

Breakdowns: pooled; by mutation family; by source tier (S1, S2); by contract
tier; by TF32 policy; c@1e-3 versus c@1e-2.

These definitions are implemented in `harness/q1/analysis.py` (ladder
composition, tiers, splits, intervals, cost) and run by
`scripts/report_q1_stage0.py` on the journal's final rows; that code is part
of the frozen revision.

## 7. Stage 0 acceptance (all required before any Stage 1 work)

1. **Fidelity** (GPU jobs on the unmodified upstream code):
   - gate `a` agrees with unmodified KernelBench@44130946
     `eval_kernel_against_ref` on 100% of items, and `a_head_1e-4` with
     @423217d9, except the disagreements listed in advance: none for `a`;
     for `a_head_1e-4`, items where the HEAD reference raises (L1/95 class),
     which upstream reports incorrect and Q1 reports unrefereeable;
   - `b1` and `b2` agree with unmodified KernelGYM `triton_detect` and
     `compute_triton_kernel_coverage` on 100% of items;
   - `c1` in KBV-compatibility mode (inherited RNG, every tensor cast to
     fp32, no validity filter) agrees with unmodified KBV
     `run_hidden_correctness_check` on KBV's own problem copy on 100% of
     items; expected disagreements of the primary `c1` with KBV come only from
     the two documented deviations;
   - every a-versus-b0 disagreement is listed with its cause.
2. **The primary audit rejects 0 evaluation-set correct substrates**, except
   adjudicated natural faults. A natural fault needs a concrete witness input
   deviating from fp64 beyond T and independent evidence (an upstream fix
   commit, or a second implementation that agrees with fp64). Otherwise the
   rejection is an audit bug: version bump and rerun.
3. **FRR(c) ≤ 2% with Clopper-Pearson 95% upper bound ≤ 5%**, on at least 72
   independent evaluation-set correct kernels. With n = 72 this requires 0
   rejections; with n = 110 at most 1. If fewer than 72 are admitted, the
   criterion is reported as not met (under-powered), not waived.
4. **Unadjudicated audit holes = 0.**
5. **Positive controls**:
   - b1 rejects every reference-identity control in every replicate;
   - gate `a` and the audit accept every reference-identity control;
   - KernelBench's `result_reuse` and `zero_out` kernels are rejected by `a`
     at both revisions, as their upstream unit tests assert;
     `non_default_stream` is reported (upstream flags it by timing, not
     correctness);
   - hack-emulating mutants are accepted by `a` and rejected by `c` and the
     primary audit.
6. **FAR(a) is reported beside Measuring the Checker's 16.9%** with no
   threshold (different language, substrates and rule port).

## 8. Sample size and precision

- Correct kernels: S1 covers up to 196 problems; with about 190 admissible,
  S1-eval is about 95, plus about 19 adapted S2 kernels, so n ≈ 110 is
  expected; 72 is the minimum for criterion 3. Exact 95% upper bounds with 0,
  1, 2 rejections: n = 72: 5.0%, 7.5%, 9.7%; n = 95: 3.8%, 5.7%, 7.4%;
  n = 110: 3.3%, 5.0%, 6.4%. At n = 110 the criterion passes with probability
  0.90 if the true FRR is 0.5%, 0.70 at 1%, 0.35 at 2%.
- Mutants: at most 40 per substrate; about 1,000-1,400 witnessed test mutants
  are expected. At FAR ≈ 17% the exact 95% interval is ±2.4 pp at n = 1,000
  and ±2.0 pp at n = 1,400 before clustering; the problem-cluster bootstrap
  widens it and is the reported interval.
- Stage 0 has no hypothesis test that would need an MDE; its decisions are the
  acceptance criteria above. Stage 1's power gate is in section 11.
- Priors used for planning only (zero-GPU, released data;
  `program/evidence/2026-10-07/q1-lethe-priors.json`): among lethe's 2,453
  gated cold-start kernels with `final_speedup > 0` and no BatchNorm, Dropout
  or `self.training` in the reference, 27.4% (95% CI 25.6-29.2%) fail lethe
  CMP-01 or CMP-03; Measuring the Checker's realism probe found 3 of 60
  incorrect (5.0%, CI 1.0-13.9%).

## 9. Execution, budget and exclusions

- GPU work runs only as Slurm jobs through the Docker lane (merged into main
  at 1f18cae) with `model: {kind: none}`, `container_profile: large-cpu-mem`,
  an explicit `memory_gb` and `seed_binding`, from a clean host clone and a
  source-overlay image of the frozen revision. Templates:
  `experiments/manifests/q1-core/`.
- Budget: pilot at most 1 GPU-h; Stage 0 total at most 8 GPU-h. If the pilot
  projects more than 8, the research gauntlet runs before the full run, or the
  configuration shrinks (c-lite) by a new addendum.
- Watchdog per item: compile 120 s, correctness 180 s, timing 300 s; the first
  timeout ends that kernel's gate or channel item. A timeout is a rejection by
  that gate and an A4 failure for the audit.
- A worker that dies after the candidate loaded is a rejection; one that dies
  before is an error.
- **Infrastructure failures** (excluded and always listed): a GPU health
  check that fails after a crash or timeout (the item becomes `error`,
  `infra_failure`, and the slot is retired); a lane prolog refusal (no job
  starts); a job interrupted by the signal checkpoint (killed items are not
  journaled and rerun); a reference that raises at native inputs (problem
  unrefereeable for that gate). An infrastructure-failed item is retried once
  as a new attempt; if it fails again it is excluded.
- Timing: randomized paired order over 30 kept rounds after 10 warm-up calls
  per side, L2 flush before each call, CUDA events, median of per-round
  ratios with a bootstrap 95% CI (B = 10,000, seed 0), TF32 and strict-fp32
  baselines, throttled rounds dropped and counted, only on the dedicated
  timing GPUs 6 and 7, with the lane prolog's foreign-process result recorded;
  the noise floor is measured with GPUs 0-5 idle and loaded.

## 10. Always reported

Every metric in section 6 for every gate variant, under both TF32 policies,
for all contract tiers and the c-disjoint verdict, on test and (labelled) dev
mutants; MS/FAR per family and tier; the c@1e-3 versus c@1e-2 decomposition;
KBV-raw; audit-hole counts and their adjudications; precision-only kernels;
A3 refusal, crash and silent-wrong counts; inadmissible and unrefereeable
configuration counts; excluded and infrastructure-failed items with causes;
cost per gate and the c/b ratio; every fidelity disagreement; FA-share
(uninterpreted); the audit version and whether M was raised; and FAR(a)
beside 16.9%. A negative or failed acceptance criterion is reported, never
dropped.

## 11. Pre-committed Stage 1 rules (bind the Stage 1 preregistration)

Stage 1 (on-policy false-accept audit) needs its own experiment id, the R580
driver or Kevin's written risk acceptance (D2), the research gauntlet, and
Kevin's choice of policy model (D5). These rules are fixed now so Stage 0
results cannot shape them:

- Proceed to the three-arm RL comparison only if FA-share(a) - FA-share(c) ≥
  3 pp and FA-share(b) - FA-share(c) ≥ 3 pp, each with non-overlapping 95%
  task-cluster bootstrap intervals, and median GPU-seconds of c (or c-lite) at
  most 2x those of b per kernel, under the primary tier (G) and TF32 policy
  (TF32-admissible).
- Decisive negative: the 95% upper bound of FA-share(a) below 3 pp, or fewer
  than 30 audit-rejected kernels among those gate (a) accepts.
- Power gate: before sampling, a pilot-calibrated simulation must give power
  at least 0.8 at a 4 pp difference; otherwise samples per task rise to 16
  within budget or the run is labelled under-powered in advance. (The reviewed
  plan's simulation, 250 tasks x 8 samples, acceptance about 55%, ICC 0.3,
  gave power 0.47 at 3 pp and 0.67 at 3.5 pp for the non-overlap rule.)
- Strata reported separately: KernelBench L1, KernelBench L2 (Dr. Kernel's
  validation set), RL-training tasks.

## 12. Design decisions taken in this draft

Decisions D3, D5, D6, D7 and D14 are applied as written. Choices the reviewed
plan left open, with reasons:

1. A3 adds `inner137`, a held-out prime above native size. Without it every A3
   shape is at or below native, so a kernel that covers only up to its native
   size is invisible to the audit and every such gate-(c) rejection would
   become an unadjudicable audit hole.
2. A4 runs on a signed (randn) draw as well as the native draw. Native
   `torch.rand` inputs are non-negative, which hides value-dependent
   in-place writes (an in-place ReLU leaves them unchanged).
3. The A2/A3 validity gate uses the audit's own metric (`max e(r32) <= 1e-3`
   and matching non-finite masks), the analogue of gate (c)'s 1e-3 ceiling.
4. `b1`/`b2` errors count as accept in the ladder, matching the released
   fail-open behavior; they are counted separately.
5. Watchdog limits are the fixed 120/180/300 s per phase rather than a
   multiple of reference runtime, so limits are known before any timing.
6. Gate (a)'s record implementation is a device-generic transcription of the
   44130946 code (it also serves the tolerance and HEAD variants); fidelity
   criterion 1 requires 100% agreement with the verbatim vendored upstream.
7. The KernelGYM spec-first split was done by one agent writing the spec and
   then implementing from it, not by two agents; the b1/b2 differential
   against the unmodified clone is the check that matters.
8. No GPU smoke ran before this draft. The lane submitter it needs was merged
   into main (1f18cae) only after this branch was cut, and the lane runs the
   code embedded in a source-overlay image; the smoke
   (`scripts/run_q1_gpu_smoke.py`, reference problems as their own kernels) is
   the first GPU job after review and is infrastructure validation, not data.
