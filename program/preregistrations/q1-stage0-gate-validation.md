## 1. Question and claim boundary

Question Q1 (`program/questions/q1-kernel-gate-strength.md`), Stage 0: build
three kernel correctness gates of increasing strength and an independent audit
that no gate sees, and measure, on compiler-generated and pre-2025
human-written Triton kernels and their deterministic mutants, (i) how often
each gate accepts a kernel the audit rejects, (ii) how often each gate rejects
a correct kernel, and (iii) what each gate costs. Stage 0 also builds and
validates the corpus it measures on: which substrates enter, which mutants
exist, which are scored and how they are weighted.

Claim boundary: Stage 0 validates the instrument. Mutants are not policy
faults, so no Stage 0 number answers whether a stronger gate changes what RL
learns, and the false-accept share (FA-share) is computed but not interpreted.
Stage 0 runs no model-written kernel on a GPU (decisions D3, D7): the corpus
is TorchInductor output, pre-2025 human-written kernels, deterministic
mutants of both derived by reviewed harness code, launcher-level controls
generated by that code around them, and KernelBench's own reference models
and adversarial kernels.

## 3. Corpus

### 3.1 Substrates

**S1 (TorchInductor).** For each of the 196 problems, `torch.compile(model,
dynamic=True, fullgraph=True)` under `torch.no_grad()` with Inductor
`deterministic=True`, `triton.autotune_pointwise=False`, caches disabled,
Dynamo `assume_static_by_default=False`, `specialize_float=True` and duck
sizing off. Canonical codegen runs on one H100 (`mode=cuda`) inside the
admission job; the mock-H100 CPU build is a dry run only. A problem whose
default output calls a library GEMM or convolution is recompiled with
`max_autotune=True` and `max_autotune_gemm_backends="TRITON"`; the template
build is kept only if Inductor's deterministic choice
(`pick_deterministic_choice`) is a Triton template (it never is for
convolutions, so L1 convolutions yield no S1 substrate). Each kernel uses the
first config its heuristic returns (`first-of-n` recorded where there are
several). Conversion follows `harness/q1/substrates/inductor_convert.py`
(`q1-inductor-convert/1`): kernel text verbatim minus the heuristic decorator,
plain `kernel[grid](...)` launches with Inductor's compile options, grids from
Inductor's `GridExpr`, and Dynamo/Inductor guards (tensor dtype, rank and
device; shape guards; symbol ranges, sizes at least 2; pinned scalar inputs)
raised as `SubstrateRefusal` before any launch. A problem yields no S1
substrate, with its reason code recorded, when codegen fails or conversion
would be unfaithful (`ConversionError` codes).

**S2 (human-written, pre-2025).** Exactly the 25 entries of
`s2_catalog.CATALOG` (18 kernel families), built with their recorded edits
(`q1-s2-build/1`): `strip-libentry`, `drop-debug-prints`, `pin-autotune` (the
first listed config that compiles for sm_90 at fp32; index 1 only for the
tutorial matmul, whose config 0 needs 294,912 B of shared memory),
`tl-math-to-libdevice`, `liger-inline-utils` and the `tutorial-*` edits. Each
substrate stores `normalization.diff` and the upstream excerpt with its
licence. The tutorial matmul keeps default-precision `tl.dot` (TF32) and is the
TF32-policy control. No entry is added, removed or edited after the freeze.

### 3.2 Admission (`q1-substrate-admission/1`)

A built substrate is admitted if and only if:

1. `check-static` passes: `ModelNew` present, plain `kernel[grid]` launches
   only, no `libentry`, `triton_heuristics` or static launcher;
2. `check-compile-native` passes: every launched kernel compiles for sm_90 at
   native shapes on the meta device; where host code cannot run on the meta
   device (it reads a tensor value, such as Liger cross-entropy's `.item()`),
   this check is recorded as not applicable and rule 3 decides;
3. GPU admission at native shapes, seed 42: gate (b)'s `LaunchHook`
   (`harness.q1.gates.gate_b`) records at least one launch under
   `torch.inference_mode()` and under `torch.enable_grad()`, each after one
   unhooked warm-up call; `refuse`, `reject` (no launch) and `error` mean not
   admitted, with the verdict recorded as an `admission_hook` row;
4. for S1 only, `check-interp` (Triton interpreter on small CPU inputs, 1e-3)
   does not report `fail`; a `fail` marks the substrate `conversion-suspect`
   and excludes it. Interpreter limitations (`no-small-shape`, `unsupported`,
   `error`, `timeout`) do not exclude; S2 interpreter results are reported only.

Admission says nothing about correctness. A **correct substrate** (the FRR
denominator) is an admitted evaluation-set substrate that the primary audit
(tier G, TF32-admissible) accepts at replicate 42. The schema gate id
`admission_audit` is not emitted: correctness comes from the audit rows of
this experiment.

### 3.3 Mutants (mutator `harness/q1/mutate/`, 68 operators)

1. **Enumeration.** Each operator (64 ports of KernelBench-M rules tagged
   `paper`, 4 `triton-only`: `relu-where-remove`, `atomic-add-to-store`,
   `atomic-rmw-split`, `dot-tf32`) is applied to every scope of each admitted
   substrate's `kernel.py`: each `@triton.jit` body and the launch code. One
   site per candidate (`acc-fp16` changes an accumulator's declaration and its
   updates together). Order: registry (schema family) order, then jit functions
   in source order and the launch scope, then position. No randomness.
2. **CPU dedup.** A candidate must parse; `dedup_hash` is the SHA-256 of its
   normalized AST. Candidates equal to the parent are dropped as equivalent; a
   later duplicate is dropped and recorded with the operator that kept it.
3. **Specialization record** (one GPU job, parents only). One native forward
   pass of each admitted parent (seed 42, inputs created on the GPU) under
   Triton's `knobs.runtime.jit_post_compile_hook` records the serialized
   specialization of every kernel compiled. No mutant runs in this step.
4. **Compile filter** (GPU-less container). Parent and candidates are compiled
   at every recorded specialization with `TRITON_DISABLE_LINE_INFO=1` for
   sm_90. A candidate is `compile-fail` (Triton error, more than 600 s for one
   kernel, or no result after two isolated retries), `equivalent-to-parent`
   (same cubin SHA-256 at every recorded specialization and the same
   launch-scope AST), `duplicate` or `distinct`. If any parent fails to
   compile, the corpus is not built.
5. **Cap.** At most 40 distinct mutants per substrate: families by
   water-filling (equal shares capped by availability, leftovers to the largest
   remaining availability, ties by family order), then operators within a
   family the same way (ties by operator name), then a simple random sample in
   each operator stratum, drawn with `random.Random` seeded from
   `sha256("q1-mutant-cap/{seed}/{substrate_id}/{family}/{operator}")` over the
   stratum sorted by `dedup_hash`. Each kept mutant records `k/n` and its
   Horvitz-Thompson weight `n/k`.
6. **Cap seeds.** 42 is primary; 43 and 44 draw alternate samples on the CPU.
   Mutants only those samples select are scored only if the pilot cost card
   keeps the Stage 0 total at or under 8 GPU-h; otherwise they are reported as
   not scored.

### 3.5 Splits (fixed now)

- **S1 calibration split** (`harness/q1/substrates/split.py`,
  `q1-s1-split/1`): over all 200 vendored L1/L2 problem ids, drop the 4
  excluded ids, then per level sort the ids by (level, number), shuffle with
  `random.Random(f"{seed}:L{level}")` at seed 42, and put the first
  `ceil(n / 2)` in calibration (S1-cal) and the rest in evaluation (S1-eval).
  Result: 98 calibration and 98 evaluation problems (L1 50/50, L2 48/48),
  split SHA-256 `b773f218f174e3bb8ab4fcde4f4e6318d870ef020e6b86bce807362c5292a0b2`.
  It depends only on the problem list and was computed before any substrate
  was built. A substrate that fails admission leaves its half; it never moves.
  S2 substrates are evaluation-only. S1-cal is used only for audit calibration
  (section 6.1).
- **Mutant dev/test split** (`harness/q1/mutate/sampling.py`): a kept mutant
  is `dev` if the first byte of
  `sha256("q1-mutant-split/v1/seed=42/{substrate_id}/{dedup_hash}")` is even,
  else `test`, whatever cap seed drew it. Dev is used only to choose c-lite
  (section 5.5); every primary mutant metric is on test, and dev is reported
  separately and labelled. A secondary problem-level split applies the same
  rule to `sha256("q1-problem-split/v1/seed=42/{problem_id}")`.

`harness.q1.analysis` reads both splits from these functions (`s1_split`,
`mutant_split`); the report records the S1 split hash.

## 4. Seeds and units

- Seeds 42, 43 and 44 are full-stack scoring replicates: gate (a)'s
  `seed_num`, and the draw seeds of gate (c) and the audit, shift with the
  replicate. Replicate 42 is primary; 43 and 44 are robustness replicates.
- Draw seeds per channel (`harness/q1/gates/outcome.py::channel_seed`):
  `base + index + 100 * (replicate - 42)` with bases c1 1042, c2 2042, c3
  3042, A2 4042, A3 5042, A1 6042, A5 7042. Gate (a) derives its five trial
  seeds as KernelBench does (`torch.manual_seed(seed)`, then five
  `torch.randint(0, 2**32 - 1, (1,))`).
- Corpus seeds: the cap seed (42 primary; 43 and 44 alternate samples), the
  split seed 42 and the S1 split seed 42; admission uses seed 42 only (launch
  visibility is a property of the launch path, not of input values).
- Unit of analysis: the kernel (substrate, mutant or control). Seeds are not
  independent units. Pooled metrics use a problem-cluster bootstrap
  (B = 10,000, seed 0); FRR uses exact Clopper-Pearson 95% intervals over
  kernels.

## 5. Gates (frozen)

All gates run with models in training mode, each gate and each audit channel
in its own process (`harness/q1/runner.py`), torch TF32 flags at their process
defaults (matmul TF32 off, cuDNN TF32 on; `tf32_policy = torch-default`).

### 5.1 Gate (a)

- **a (primary)**: KernelBench@44130946 `eval_kernel_against_ref` +
  `run_and_check_correctness` semantics with `num_correct_trials=5`,
  `seed_num=42`, `backend="triton"`: inputs from the problem's `get_inputs()`
  at native shapes, moved to the device without a dtype cast (integer targets
  keep their dtype), the same input objects passed to the reference and then
  to the candidate under `torch.no_grad()`, output shape check,
  `torch.allclose(ref, out, atol=1e-2, rtol=1e-2)`; all five trials must pass.
- Secondaries: `a_1e-3` (same, tolerance 1e-3), `a_head_1e-4` and
  `a_head_1e-2` (KernelBench@423217d9 semantics: every tensor cast to fp32,
  tolerance 1e-4 or 1e-2), `a_static` (`a` and HEAD
  `validate_kernel_static(code, backend="triton", precision="fp32")`).
- A reference that raises (for example L1/95 under the HEAD fp32 cast) makes
  the item unrefereeable for that variant (verdict `error`, excluded from that
  variant's denominators, always counted and reported).

### 5.2 Gate (b)

- `b1`: a Triton launch is recorded under both `torch.inference_mode()` and
  `torch.enable_grad()` (warm-up 1 outside the hook, 1 hooked step each),
  inputs from `set_seed(42); get_inputs()` without a cast.
- `b2`: in a `torch.profiler` window (CPU and CUDA activities) after 3 warm-up
  and 10 timed calls, holding a 1024-element self-test and 10 calls: decoy if
  the event table has at least one row with positive device time and no row
  matches a captured kernel name (case-insensitive equality or substring
  either way).
- **b (ladder) = a and b1 and b2.** As released, detection errors fail open:
  a `b1` or `b2` row with verdict `error` counts as accept in the ladder and
  is reported separately.
- `b_native`: the unmodified KernelGYM clone's `eval_kernel_against_ref`
  (b0 and b1 and b2), fidelity only.

### 5.3 Gate (c)

**c = b and c1 and c2 and c3**, each family at atol = rtol = 1e-3.

- `c1`: KBV hidden configurations per problem from `kbv_hidden_configs.json`
  (D1 x1.0, D2 x3.0, D3 x0.01, D4 x-1.0 applied to floating tensors; L1/90
  drops D2; L1/98 drops D4; L1/100 adds D5 alternating +-1 targets).
  Deviations from KBV, documented: configuration `i` draws after its own seed
  (section 4); integer tensors keep their dtype.
- `c2`: S-half (leading free root halved), S-double (inner free root doubled,
  reduced to the largest value within 2x native input bytes), S-small (every
  free root divided by 8), each drawn with D1 and D4.
- `c3`: U1 (one free root + 1), U2 (one free root to `(d - d mod 128) + 17`),
  U3 (leading root = 3), and for L1 matmul problems MM1 and MM17 (every free
  root to `(d - d mod 64) + 1` or `+ 17`), each drawn with D1 and D4.
- **No c configuration sets a free root below 2** (S-half, S-small and MM1 are
  floored at 2; `shapes.C_MIN_SIZE`). Compilers specialize sizes 0 and 1, and
  the S1 substrates refuse them before any launch, so a size-1 configuration
  would make gate (c) reject a correct, merely specialized kernel for a refusal
  that says nothing about silent wrong output. Size 1 stays in the audit
  (`A3/lead1`), where a refusal is classified (section 6.3).
- Free roots are found by static scope analysis (`harness/q1/problems.py`):
  module integer constants reached from `get_inputs` that neither
  `get_init_inputs` nor `class Model` reads; `get_init_inputs()` is checked
  unchanged for every configuration.
- Secondaries from the same outputs: `c_1e-2` (tolerance 1e-2) and
  `c_kbv_raw` (no validity filter; a configuration whose reference raises
  passes, as in KBV).

### 5.4 Validity gate (every c configuration)

A configuration counts only if (i) the fp32 reference output is finite,
(ii) the device fp32 reference is within atol = rtol = 1e-3 of an fp64 replay
of the same model and inputs, and (iii) a CPU fp32 reference is within the
same tolerance of the device reference; integer outputs must match exactly. A
configuration whose reference raises is inadmissible. Inadmissible
configurations are logged; a kernel with no admissible configuration in a
family is unrefereeable in that family (`error`), reported, and excluded from
that family's denominators.

### 5.5 c-lite

If the measured median GPU-seconds of `c` exceed 2x those of `b` per kernel
in the pilot, a reduced configuration set is chosen by greedy set cover on the
dev mutants (maximize newly rejected audit-witnessed dev mutants per
GPU-second; ties by configuration id) and frozen in an addendum
preregistration with a new experiment id before any test mutant is scored.

## 6. Independent audit (frozen at v1 after calibration)

No gate reads audit inputs or verdicts, and the audit reads no gate output.

### 6.1 A1, fp64 oracle (decision D14)

- `e(x) = max_i |x_i - r64_i| / (|r64_i| + 1e-3 * ||r64||_inf)` over
  positions where both are finite; NaN, +Inf and -Inf masks must equal the
  oracle's. The oracle is a deep copy of the reference with parameters,
  buffers and floating inputs in fp64, in training mode.
- Pass if `e(candidate) <= T`, `T = max(M * max(e(r32_device), e(r32_cpu)),
  2^-20)`, `M = 16`.
- **TF32 policy, primary = TF32-admissible**: when the reference dispatches a
  matmul or convolution op, or the candidate source calls `tl.dot`, T is also
  computed from a device reference with matmul and cuDNN TF32 on, and the
  larger T is used. **Secondary = strict-fp32** (device reference with both
  TF32 switches off). Both are always reported.
- Integer and bool outputs: exact match with the oracle under torch's
  first-index tie rule, except at positions where an fp32 reference itself
  disagrees with the oracle (a near-tie certified by the fp64 replay), where
  the candidate may match that fp32 reference.
- Draws: five native `get_inputs()` draws (seeds 6042-6046 at replicate 42).
- Precision-only class: fails A1, every failing draw within 64·T, passes A2,
  A3 and A4. Reported as its own class.
- **Calibration**: on S1-cal correct substrates only, compute each one's
  required multiplier `e(candidate) / max(e(r32_device), e(r32_cpu))` over its
  A1 draws. If the largest exceeds 16, M is raised once to the smallest power
  of two at least that large. The audit is then frozen as v1 by
  `audit_version_hash` (constants plus SHA-256 of every audit file), before
  any evaluation-set kernel or mutant is scored. Any later change is a new
  audit version, a full rerun, and a disclosed change in every reported number.

### 6.2 A2, held-out values

Seven distributions replace every floating input at native shape: randn,
U[-8, 8], U[0, 1) x 100, spiky (0.1% of entries and the last element along
every axis x1000), ties (U[-4, 4] rounded to 1/8), all-negative, constant
rows. Each draw passes the audit validity gate: the reference runs, its fp32
non-finite masks equal the oracle's, and `max(e(r32_device), e(r32_cpu)) <=
1e-3`. Verdict by the A1 rule.

### 6.3 A3, held-out shapes and refusal classification

From the manifest's A3 configurations (disjoint from every c value of the same
root): `lead1`, `lead5`, `inner37` (largest prime at most 0.37 x native, or
the smallest disjoint prime above it when none exists below), `inner137`
(smallest prime at least 1.37 x native, within 2x native bytes), `allprime`
(every free root to the largest disjoint prime at most 0.37 x native, same
fallback). Validity as A2. Each draw is classified: pass; silent-wrong (no
exception, fails the A1 rule); crash-after-launch (exception after at least
one Triton launch); refusal-before-launch (exception before any). The channel
verdict is `reject` on any silent-wrong or crash-after-launch draw, else
`refuse` on any refusal, else `accept`.

### 6.4 A4, tolerance-free contracts

On the first A1 draw and on one randn draw: five-run byte determinism; no
storage shared between the five live outputs; no output sharing storage with
an input; inputs byte-identical after each call; dual poison (outputs
byte-identical when fresh `torch.empty*` allocations are filled with 0x00 and
with 0xFF; on GPU additionally through the `CUDAPluggableAllocator` in
`audit/poison_alloc.c`, run by `audit/gpu_probes.py` in two fresh processes);
`compute-sanitizer --tool memcheck` clean at the smallest A3 configuration (by
input bytes); no watchdog timeout. A4 is the conjunction of the in-process,
poison-allocator and sanitizer rows. A sanitizer run that does not complete
(exit code other than 0 or 86) is reported as `error`, not as a fault.

### 6.5 A5 (secondary tier)

lethe-style EXC-01 (NaN/+-Inf scatter, masks agree), EXC-02 (subnormals),
PRC-01 (fp16, bf16 regimes), PRC-02 (fp16 inputs vs fp32 reference) with
three fixes to lethe's adapter: models stay in training mode (lethe calls
`.eval()`), every floating input is perturbed (lethe perturbs the first), and
the reference shares the candidate's weights.

### 6.6 Contract tiers (decision D14; primary = G)

- **N** = A1 and A2 and A4 at native shapes.
- **G** = N and A3, where refusal-before-launch is "non-general", not a fault.
  This is the primary tier: never silently wrong at held-out shapes.
- **G-strict** = N and A3, refusals count as faults.
- **c-disjoint** = A1 and A4 (channels gate (c) does not share).

All four are always reported under both TF32 policies. Schema gate ids:
`audit_N`, `audit_G`, `audit_G_strict`, `audit_c_disjoint`.

### 6.7 Audit holes

A kernel rejected by a gate on a validity-gated input that the primary audit
accepts is replayed on that input against the fp64 oracle with the frozen T.
Deviation beyond T: an audit hole (audit version bump and full rerun).
Otherwise: a false rejection by that gate.

## 7. Metrics

### 7.1 Gate metrics

For each gate g in {a, a_1e-3, a_head_1e-4, a_head_1e-2, a_static, b, c,
c_1e-2, c_kbv_raw, c-lite if adopted}:

- **witnessed mutant**: rejected by the primary audit (tier G,
  TF32-admissible) on some validity-gated input;
- **MS_g** = witnessed mutants rejected by g / witnessed mutants;
  **FAR_g** = 1 - MS_g;
- **FRR_g** = correct substrates (section 3.2) rejected by g / correct
  substrates; FRR(c) is also split by cause from the per-configuration rows
  (`analysis.c_rejection_causes`: candidate raised, numerical mismatch, shape
  mismatch);
- **audit-hole_g**: count from section 6.7;
- **cost_g**: GPU-seconds per kernel from worker spawn to verdict (compile
  included), median and p95, marginal and amortized; ratios c/b and c-lite/b;
- **FA-share_g** = (accepted by g and audit-rejected) / accepted by g:
  computed, not interpreted (it depends on the mutant mix).

Breakdowns: pooled; by mutation family; by `paper` versus `triton-only`
operator origin; by source tier (S1, S2); by contract tier; by TF32 policy;
c@1e-3 versus c@1e-2. Mutant metrics are reported unweighted and weighted by
`n/k` (the uncapped natural mix). MS/FAR per family for a, b and c are
reported beside Measuring the Checker (2609.22220) Table 2 (arithmetic 8.7%,
indexing 14.4%, semantic 14.9%, boundary 22.9%, synchronization 27.8%,
precision 78.6%, all 16.9%), descriptively, with no threshold.

These definitions are implemented in `harness/q1/analysis.py` and run by
`scripts/report_q1_stage0.py` on the journal's final rows; both are in
`analysis_sha256`.

### 7.2 Corpus metrics (no GPU; unit = substrate or candidate mutant)

- Substrates: built, admitted and excluded counts by tier, level, split half
  and reason code; triton-only versus hybrid-library S1; mock-versus-device
  codegen parity per S1 problem; interpreter outcomes; registers, stack and
  shared memory per kernel; and **`n_eval_independent`** = admitted S1-eval
  substrates (one per problem) plus admitted S2 kernel families (a family with
  several admitted problems counts once).
- Mutants: C1 yield (CPU-distinct candidates per substrate, family and
  operator; rejections by reason); C2 compile filter (compile-fail by error
  kind, equivalent and duplicate fractions); C3 selection (kept per family,
  weight distribution); C4 split balance (dev share overall and per family);
  W1 witness rate per family (unwitnessed mutants are counted and excluded
  from MS/FAR).
- Controls: the verdict of every control for every gate in its `expected` map,
  at each replicate (the control matrix K).

## 8. Decision rules and acceptance (all required before any Stage 1 work)

### 8.1 Corpus rules

- **D-1, FRR feasibility.** If `n_eval_independent` is at least 72, the FRR(c)
  criterion (8.2, item 3) is evaluable as written. Between 60 and 71: report
  it as under-powered with its actual n, without augmenting the evaluation
  set. Below 60: stop before any gate scoring and refer the corpus to the
  program owner.
- **D-2, converter fault.** If more than 5% of converted S1 substrates are
  `conversion-suspect`, the converter is presumed wrong: fix it as a new
  converter version, rebuild every S1 substrate, rerun all checks, report both.
- **D-3, mock path.** If more than 10% of S1 problems differ between mock and
  device codegen, the mock path is declared unreliable for future CPU-only
  builds; the corpus always uses the device build, so membership is unchanged.
- **Determinism.** Two independent runs of pool, compile and select from the
  same substrates, records and code produce byte-identical `mutants.jsonl` and
  `manifest.json`, and the same set of `compile.jsonl` rows.
- **Compile-filter sanity** on the frozen image: every parent compiles;
  compiling each parent twice gives identical cubin hashes; on the toy probe a
  reformatted kernel and a flipped comparison hash equal to the parent while
  `<` to `<=` and ReLU removal do not.
- **Coverage.** At least 5 of the 6 families have at least 30 witnessed test
  mutants. A family below 30 is reported with its counts and intervals and
  marked "not estimable"; it does not fail the corpus. If fewer than 300
  witnessed test mutants exist in total, every mutant metric is labelled
  under-powered.

### 8.2 Gate-validation acceptance

1. **Fidelity** (GPU jobs on the unmodified upstream code):
   - gate `a` agrees with unmodified KernelBench@44130946
     `eval_kernel_against_ref` on 100% of items, and `a_head_1e-4` with
     @423217d9, except the disagreements listed in advance: none for `a`;
     for `a_head_1e-4`, items where the HEAD reference raises (L1/95 class),
     which upstream reports incorrect and Q1 reports unrefereeable;
   - `b1` and `b2` agree with unmodified KernelGYM `triton_detect` and
     `compute_triton_kernel_coverage` on 100% of items;
   - `c1` in KBV-compatibility mode (inherited RNG, every tensor cast to
     fp32, no validity filter) agrees with unmodified KBV
     `run_hidden_correctness_check` on KBV's own problem copy on 100% of
     items; expected disagreements of the primary `c1` with KBV come only from
     the two documented deviations;
   - every a-versus-b0 disagreement is listed with its cause.
2. **The primary audit rejects 0 correct-substrate candidates in the
   evaluation set**, except adjudicated natural faults. A natural fault needs a
   concrete witness input deviating from fp64 beyond T and independent
   evidence (an upstream fix commit, or a second implementation that agrees
   with fp64). Otherwise the rejection is an audit bug: version bump and rerun.
3. **FRR(c) ≤ 2% with Clopper-Pearson 95% upper bound ≤ 5%**, on at least 72
   independent correct evaluation-set kernels (D-1). With n = 72 this requires
   0 rejections; with n = 110 at most 1. If fewer than 72 are available, the
   criterion is reported as not met (under-powered), not waived.
4. **Unadjudicated audit holes = 0.**
5. **Controls**: every expectation of every control (section 3.4) holds in
   100% of control x gate x replicate cells under the primary TF32 policy
   (`analysis.control_checks`; a missing cell counts as a failure). A mismatch
   blocks Stage 0 results until it is classified as a gate or audit bug (fixed
   in a new version and rerun), a control bug (new control version and rerun)
   or a false premise (the expectation is withdrawn in a new preregistration
   id, never by editing this file).
6. **FAR(a) is reported beside Measuring the Checker's 16.9%** with no
   threshold (different language, substrates and rule port).

## 9. Sample size, precision and power

- **Correct kernels.** From the CPU dry run (mock codegen; infrastructure,
  not data): 156 of 196 problems convert to S1 (81 evaluation, 75
  calibration), 35 yield no Triton kernel, 5 fail mock codegen (to be retried
  on the device); with all 81 S1-eval candidates and the 18 S2 families
  admitted, `n_eval_independent` = 99. Exact 95% upper bounds with 0, 1, 2
  rejections: n = 72: 5.0%, 7.5%, 9.7%; n = 99: 3.7%, 5.5%, 7.1%; n = 110:
  3.3%, 5.0%, 6.4%. So criterion 3 tolerates no false rejection below n = 110.
  At n = 110 it passes with probability 0.90 if the true FRR is 0.5%, 0.70 at
  1%, 0.35 at 2%.
- **Mutants.** At most 40 per admitted substrate (at most about 7,200 for
  about 180 substrates), about half in test. For a family with n witnessed test
  mutants, a miss rate near 0.2 and a problem-cluster design effect of 2, the
  95% half-width is about 11.1 points at n = 100, 6.4 at 300 and 3.5 at 1,000;
  the design effect is estimated from the data and reported. Pooled, at FAR
  about 17% the exact interval is ±2.4 pp at n = 1,000 before clustering.
- **Detectable difference between gates.** Gates are nested, so `MS_c - MS_a`
  is a one-directional paired difference with variance about `d / n` for a
  discordant share d. With 80% power at two-sided alpha 0.05 and design effect
  2, the smallest detectable difference is about `7.84 x 2 / n`: 5.2 points at
  n = 300 and 1.6 points at n = 1,000 witnessed test mutants.
- Stage 0 has no hypothesis test beyond these acceptance criteria. Stage 1's
  power gate is in section 12.
- **Priors** for planning only (zero-GPU, released data;
  `program/evidence/2026-10-07/q1-lethe-priors.json`): among lethe's 2,453
  gated cold-start kernels with `final_speedup > 0` and no BatchNorm, Dropout
  or `self.training` in the reference, 27.4% (95% CI 25.6-29.2%) fail lethe
  CMP-01 or CMP-03; Measuring the Checker's realism probe found 3 of 60
  incorrect (5.0%, CI 1.0-13.9%).

## 10. Execution, budget and exclusions

- **Lane.** Every GPU step is a Slurm job through
  `scripts/submit_docker_research_job.py` (merged lane, main@1f18cae and
  142b986) with `model: {kind: none}`, an explicit `memory_gb`, either
  `container_profile: large-cpu-mem` or a Triton cache redirected to
  `/outputs`, `seed_binding` where seeds are declared, from a clean host clone
  and a source-overlay image of the frozen revision. Templates (all fail closed
  until their `FILL-*` values are written from measured artifacts):
  `experiments/manifests/q1-substrate-admission.yaml`,
  `experiments/manifests/q1-mutate/specializations-v1.yaml`,
  `experiments/manifests/q1-core/q1-gate-gpu-smoke.yaml`,
  `experiments/manifests/q1-core/q1-stage0-pilot.yaml`.
- **Order.** (1) GPU smoke (reference identity, every gate; 0.75 GPU-h cap);
  (2) substrate admission with device codegen (1.5 cap); (3) specialization
  recording (0.5 cap), then the CPU compile filter, cap and split; (4) fidelity
  jobs (about 0.5); (5) validity precompute and audit calibration on S1-cal,
  then audit v1 frozen (about 1.5); (6) pilot (1.0 cap: 8 substrates with all
  their mutants and controls, seeds 42/43/44; cost card and c/b ratio);
  (7) full run; (8) timing noise floor on GPUs 6-7 with GPUs 0-5 idle and
  loaded (about 0.5).
- **Budget.** All Stage 0 GPU jobs together are capped at 8 GPU-h. The sum of
  the expected costs above plus a 4-5 GPU-h full run is 9-10 GPU-h, so the
  pilot's projection is expected to exceed 8: in that case the research
  gauntlet runs before the full run, or the configuration shrinks (c-lite) by
  an addendum.
- **Corpus hand-off.** The lane has no hash-bound input mount for a built
  corpus. Admitted substrates, specializations and the selected mutants reach
  later jobs either inside the source capsule (committed at a recorded
  revision) or through a reviewed lane extension; each job records the
  manifest hashes it read, and a corpus whose hashes differ from the recorded
  ones is not admissible.
- **Watchdog per item**: compile 120 s, correctness 180 s, timing 300 s; the
  first timeout ends that kernel's gate or channel item. A timeout is a
  rejection by that gate and an A4 failure for the audit. A worker that dies
  after the candidate loaded is a rejection; one that dies before is an error.
- **Infrastructure failures** (excluded and always listed): a GPU health
  check that fails after a crash or timeout (the item becomes `error`,
  `infra_failure`, and the slot is retired); a lane prolog refusal (exit 75,
  `foreign_gpu_process`; no job starts); a job interrupted by the signal
  checkpoint (killed items are not journaled and rerun); a job that does not
  end `COMPLETED` with exit `0:0` (rerun as a new versioned job; partial rows
  kept and labelled, never mixed into results); a reference that raises at
  native inputs (problem unrefereeable for that gate). An
  infrastructure-failed item is retried once as a new attempt; if it fails
  again it is excluded and counted per family. Per-substrate admission
  timeouts (900 s) and CUDA out-of-memory errors are retried once in a fresh
  process; a second identical outcome is the substrate's admission verdict.
  Mutant compile errors, per-kernel compile timeouts and crashes that persist
  through two isolated retries are properties of the mutant (`compile-fail`),
  not infrastructure failures. A specialization job that does not end
  `COMPLETED` with exit 0 or logs an Xid is rerun as a whole. No other
  exclusion exists; a kept mutant is never removed after selection.
- **Timing**: randomized paired order over 30 kept rounds after 10 warm-up
  calls per side, L2 flush before each call, CUDA events, median of per-round
  ratios with a bootstrap 95% CI (B = 10,000, seed 0), TF32 and strict-fp32
  baselines, throttled rounds dropped and counted, only on the dedicated
  timing GPUs 6 and 7, with the lane prolog's foreign-process result recorded.

## 12. Pre-committed Stage 1 rules (bind the Stage 1 preregistration)

Stage 1 (on-policy false-accept audit) needs its own experiment id, the R580
driver or Kevin's written risk acceptance (D2), the research gauntlet, and
Kevin's choice of policy model (D5). These rules are fixed now so Stage 0
results cannot shape them:

- Proceed to the three-arm RL comparison only if FA-share(a) - FA-share(c) ≥
  3 pp and FA-share(b) - FA-share(c) ≥ 3 pp, each with non-overlapping 95%
  task-cluster bootstrap intervals, and median GPU-seconds of c (or c-lite) at
  most 2x those of b per kernel, under the primary tier (G) and TF32 policy
  (TF32-admissible).

  than 30 audit-rejected kernels among those gate (a) accepts.
- Power gate: before sampling, a pilot-calibrated simulation must give power
  at least 0.8 at a 4 pp difference; otherwise samples per task rise to 16
  within budget or the run is labelled under-powered in advance. (The reviewed
  plan's simulation, 250 tasks x 8 samples, acceptance about 55%, ICC 0.3,
  gave power 0.47 at 3 pp and 0.67 at 3.5 pp for the non-overlap rule.)
- Strata reported separately: KernelBench L1, KernelBench L2 (Dr. Kernel's
  validation set), RL-training tasks.

## 13. Predictions written before any GPU run

From code reading and the CPU end-to-end test; each is reported with its
outcome, and none changes a rule.

1. Every S1 substrate refuses `A3/lead1` (size 1 is below its compiled range),
   so A3 is `refuse`, tier G accepts and G-strict rejects it: FRR under
   G-strict is near 100% for S1 by construction. The CPU end-to-end test shows
   this for the S1 ReLU.
2. Gate (a)'s absolute tolerance 1e-2 hides any error on outputs whose
   magnitude is well below 1e-2. Softmax over 393,216 columns (L1/23) gives
   outputs near 2.5e-6, so gate (a) accepts a sign-flipped or zeroed softmax;
   the CPU test shows gate (a) accepting a negated softmax at 1,024 columns
   while `a_1e-3`, `c` and the audit reject it.
3. Liger LayerNorm and the tutorial LayerNorm refuse the native L1/40 row
   (4,194,304 elements), so they are not admitted.
4. FlagGems relu, gelu, silu and mul use block pointers without a boundary
   check and read and write past the end at sizes that are not a multiple of
   the block: natural faults at held-out shapes, to be classified by the audit.
5. The tutorial matmul computes `tl.dot` in TF32: rejected by A1 under
   strict-fp32 and accepted under TF32-admissible.
6. The synchronization family is small (Triton exposes only
   `tl.debug_barrier` and atomics; 5 of 2,320 mutants in a FlagGems and Liger
   robustness run) and is expected to be "not estimable".

## 15. Integration decisions (stage0/q1-gates)

1. **One preregistration.** The mutant-corpus and substrate-corpus drafts are
   merged here so corpus construction, gates, audit and analysis freeze
   together under one id and one version card.
2. **S1 split.** The substrate corpus's per-level rule over the full problem
   list replaces the core draft's split over admitted problems: it is fixed
   before any build, so admission outcomes cannot change which problems
   calibrate the audit.
3. **Mutant split.** The mutator's content-hash split replaces the core
   draft's shuffle of mutant ids: a mutant's half never depends on which other
   mutants exist, and it mirrors the paper's per-problem id-hash holdout.
4. **Gate (c) floor at size 2; audit A3 keeps size 1.** The core's shape rules
   produced 19 c configurations with a size-1 root (c2 S-small on 16 problems,
   c3 MM1 on L1/9, L1/10, L1/11), and the S1 converter refuses every dynamic
   size below 2. The S1 substrates of L1/9 and L1/11 are in the evaluation half,
   so gate (c) would have false-rejected them by construction (FRR(c) ≥ 2/99,
   upper bound above 5%). The A3 disjointness rule was also fixed: with c
   using 2 for small roots, `allprime` fell back to 2 on 14 problems; it now
   takes the smallest disjoint prime above the target.
5. **Control acceptance is the full control matrix.** Every `control.json`
   expectation must hold, replacing the core draft's shorter list; the core
   draft's "guard-drop tail" hack mutant is not produced by the mutator and is
   dropped.
6. **Core controls are built by code** (`harness/q1/controls.py`): reference
   identity for every S1-eval and S2 problem, and the three KernelBench
   adversarial kernels verbatim.
7. **One image for every step.** The mutator validated its compile filter in
   `cotcodec-research:f10a8571-architecture` and the substrate owner in the
   0b3ecef0 image (same torch and Triton); cubin equivalence must be decided by
   the same Triton and ptxas that score, so every step uses `cotcodec-q1-gates`
   at the frozen revision.
8. **Version card.** The draft names each component's hash and a test keeps
   it current; verdict rows carry `code_sha256`.
9. **One exclusion list** (`harness.q1.problems.EXCLUDED_PROBLEMS`) for every
   component.
10. **Correct substrate** is defined by this experiment's audit at replicate
    42; `admission_audit` rows are not emitted.
