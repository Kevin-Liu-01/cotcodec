# Data and artifact policy

The repository tracks contracts and portable evidence. It does not track every
byte needed to execute or reproduce locally.

## What belongs in Git

- experiment YAML and its validator;
- doctor, runner, scheduler entry point, and focused tests;
- exact revision, tree, license, archive, image, and code hashes;
- compact portable evidence generated by a deterministic sealer;
- human-readable audits with explicit claim boundaries;
- source/portfolio registry updates and durable project state.

## What stays local or remote

- model weights and tokenizer caches;
- source checkouts and source archives already represented by hashes;
- database directories, container layers, runtime caches, and build roots;
- raw benchmark corpora and large trace collections;
- full PostgreSQL, SQLite, vector-index, and stopped-state images;
- temporary staging directories and failed-run workspaces.

These paths normally live under `data/`, a versioned remote run root, or a
documented scratch location. `.gitignore` prevents accidental staging; it is not
a deletion policy. Ignored data remains user-owned and must not be removed as
part of repository cleanup.

## Portable evidence

A portable evidence file should be small enough for Git while retaining the
minimum raw artifacts needed to validate the result independently. The sealer:

1. checks the original manifest and expected roster;
2. verifies source, image, contract, runner, validator, and doctor identities;
3. validates repeat agreement and terminal status;
4. embeds bounded artifacts with deterministic gzip receipts; and
5. binds the current repository code used to interpret the result.

Large immutable inputs remain referenced by size and SHA-256 rather than being
embedded. See [`evidence-model.md`](evidence-model.md) for the claim hierarchy.

## Secrets and sensitive data

Provider keys, credentials, `.env` files, SSH material, tokens, and user data
never enter contracts, logs, evidence bundles, or Git. A no-provider experiment
must both omit the secrets and record zero provider/model calls. Before every
commit, scan the staged diff and list staged files by size.

## Retention

Keep failed attempts when they explain a launch, instrumentation, or scientific
failure. Label them precisely. Do not promote a pre-result failure into a
scientific negative, and do not rewrite a historical artifact after a later
repair succeeds.
