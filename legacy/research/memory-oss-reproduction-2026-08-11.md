# Open-Source Memory-System Reproduction

**Status (audited 2026-08-13):** versioned native protocol, deterministic
controls, exact source receipts, and historical Mem0, Graphiti, LangMem, plus
Hindsight CPU integration smokes exist. The native request was subsequently
narrowed to remove benchmark stratum; that task-blind schema patch is not a new
passing result until its contained Slurm rerun completes. BGE-backed interface
receipts exist for Mem0, Graphiti, and LangMem; Hindsight still lacks a bound
BGE receipt. Those historical BGE receipts used a now-corrected mean-pooling
transport and remain interface evidence only. The pinned model contract uses
normalized CLS pooling, so they must be rerun before a matched semantic comparison.
Docker-under-Slurm discovery is operational for actor screens, but no native
memory-system image has a digest-pinned Slurm conformance receipt. The sidecars
rebuild ephemeral state per selection and therefore do not establish persistent
CRUD, restart recovery, purge, tenant isolation, poisoning, or repair.
A long-lived subprocess transport and reference-sidecar doctor now exercise
multiple calls in one process; none of the four native adapters has migrated to
it, so this is transport evidence only, not backend persistence evidence.
**Scientific result:** none yet.

## Shared native protocol

`harness.memory_trials.systems` defines `memory-system-v1`. The harness sends a
native system only:

1. an opaque session scope;
2. ordered prefix `write`, `observe`, `update`, and `delete` events;
3. the current query; and
4. active-slot, read, top-k, and injected-token budgets.

It never sends the oracle, answer, suffix, assignment, candidate flag,
evaluation outcome, generator distractor label, source-quality annotation,
contradiction count, or proactive hint. Source event IDs, entity IDs, graph
nodes, and synthetic values are pseudonymized. Literal generator strings such
as `candidate`, `wrong`, and `distractor` cannot become a benchmark shortcut.

Benchmark stratum is now engine-owned and excluded from native-system input.
The source validator and negative tests fail if it reappears. This closes a
task-family shortcut in the wire schema; it does not establish lifecycle,
persistence, or semantic quality.

Each response must contain source-attributed records, paths, or summaries; a
complete read/write/byte/token/embedding/LLM-call/latency ledger; an immutable
implementation/config/backend/model receipt; and a binding hash. Unattributed
derived summaries cannot enter the serve-only causal arm.

The JSON subprocess implementation executes without a shell, limits response
size and time, requires a stable handshake receipt, and exposes `handshake`,
`select`, and `purge`. A separate long-lived transport reuses one process and
adds an acknowledged shutdown frame. The same wire format can run as a local
process, a digest-pinned Docker sidecar, or a service behind an agent framework.
Process reuse does not prove that a native backend retained, deleted, or
isolated any state.

## Two different estimands

The machine contract refuses to pool these modes:

### Storage plus service

The assigned candidate is included or excluded before the native system sees
the event stream. This measures the whole pipeline: write policy, extraction,
consolidation, indexing, retrieval, and service. It is the primary fair
comparison among native systems.

### Service only

Both arms construct identical memory state. At query time the harness removes
every returned item or derived path attributed to the candidate. This isolates
service exposure, but is legal only when source attribution is complete.

Calling both effects “memory benefit” would hide a real scientific difference.

## Deterministic controls

The in-process controls exercise the same contract:

- no-memory and full-prefix floor/ceiling diagnostics;
- recency over valid records;
- true LRU when the source exposes access events;
- lexical token overlap with stable recency/ID tie breaks; and
- Okapi BM25, raw-log RRF, graph-free profile expansion, and exact temporal
  graph traversal with all selected bytes charged.

Each reference algorithm is an explicit arm chosen by the study configuration,
not by hidden benchmark family metadata. Tests cover excluded generator
annotations, source attribution, separate estimands, top-k/read/token
enforcement, hash binding, and JSON process transport. The current schema patch
still requires its contained rerun before these are called passing gates.

### Matched dense-BGE floor

`dense-bge-retrieval-v1` is now implemented as a raw-record semantic retrieval
floor, not a learned memory policy. It materializes only valid task-blind prefix
records, encodes `entity_id`, `key`, and `value`, prefixes only the query with
the pinned BGE retrieval instruction, ranks normalized vectors by cosine, and
uses the same top-4/256-token/source-attribution budget as BM25. Stable ties use
write recency then source-record ID. Every encoded query or passage is charged
as an embedding operation.

The adapter fails closed unless the running encoder matches
`BAAI/bge-small-en-v1.5` revision
`5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`, its artifact and full model-receipt
digests, 384 dimensions, 512-token maximum, and `cls-l2-normalized-v1` pooling.
Tests cover semantic ranking, query-only instruction framing, attribution,
deterministic ties, non-finite/wrong-size/non-normalized vectors, model-receipt
drift, loopback-service identity drift, and atomic frozen-matrix inclusion.

The Docker/Slurm control-freeze manifest now binds BGE—not the later actor—as
the freezer workload model, and the complete signed-wave roster includes the
dense bundle. No full 500-task dense bundle or actor result has run from this
tree, so the control remains implemented but scientifically unexecuted.

## Real Mem0 smoke

The first native adapter uses reviewed Mem0 source, local Qdrant, raw
`infer=False` writes, explicit update/delete handling, exact source metadata,
and no reranker. This isolates Mem0 storage/retrieval without granting it an
unmetered extraction model. Full `infer=True` Mem0 is a later diagnostic using
the common construction model and separately counted calls.

The local CPU smoke used a deterministic 384-dimensional OpenAI-compatible
embedding endpoint. That endpoint exists only to exercise the interface and is
not a semantic embedding baseline. On generated archive task `memory-000001`:

- the native system ingested 32 ordered prefix events;
- each selection used 33 embedding calls and zero LLM calls;
- the served storage-plus-service arm returned four source-attributed items;
- the first served run used an estimated 180 injected tokens, including compact
  evidence IDs needed for actor attribution;
- repeated A/A executions matched on normalized evidence and receipts in all
  four mode/visibility cells; latency was deliberately excluded from equality;
- source-attribution and injected-token gates passed; and
- publication provenance failed, as required, because no OCI/Slurm/model
  attestation existed.

The sealed gitignored artifact internally hashes to
`63cdafdf5ac0fefe26c8b1b2a7873697cee763d9bc066370f31abb21180b74a5`.
This is real Mem0/Qdrant execution, not evidence that Mem0 improves task success.
It supersedes the earlier pre-integration smoke artifact
`5adcd8645c36a68c1b44537557cdb6cbd26dff9e1c0862cc0b1e793a72b5752d`.

## Real Graphiti + FalkorDBLite smoke

The second native adapter installs reviewed Graphiti 0.29.3 source over the
locked `graphiti-core[falkordblite]` dependency set. It uses Graphiti's public
`add_triplet` and hybrid `search` APIs over ephemeral FalkorDBLite 0.10.0.
Writes, updates, and deletes are expressed as explicit temporal triplets. The
CPU diagnostic uses the same deterministic embedding endpoint as the Mem0
interface smoke and a deterministic no-duplicate fixture at Graphiti's LLM
deduplication seam. It therefore tests an ephemeral native graph's CRUD, index,
search, and source attribution—not restart persistence or Graphiti's LLM
extraction quality.

On temporal-graph task `memory-000002`, all four estimand/visibility cells and
their A/A repeats passed. Served cells returned four source-attributed graph
edges; holdout cells returned three after candidate filtering. Injected evidence
used 230 tokens served and 172 held out. The important negative systems result
is cost: Graphiti made 180 embedding operations with the candidate and 171
without it. After correcting the common transport ledger to include embedded
database/process startup, first-run selection latency was 20.9–21.8 seconds.
Those numbers are from an isolated correctness diagnostic, not a warmed service
throughput benchmark.

The sealed artifact internally hashes to
`60aeb4c68f6809d2c8f4cc61553c827a468bd87be085d100140d9879d57da06f`;
file SHA-256 is
`beec00ccfab645255069f2229c17dcd8c2c70b56bcd4e0f264bf1eeba5fee057`.

## Real Hindsight retain/recall smoke

The fourth native adapter uses reviewed Hindsight 0.9.0 retain/recall APIs,
embedded PostgreSQL through pg0-embedded 0.15.1, `llm_provider=none` chunk
retention, the common embedding fixture, and Hindsight's RRF passthrough in
place of a cross-encoder. Reflection is disabled and remains a separate matched
construction-model diagnostic. This is Hindsight's native chunk-store path,
not its full fact/entity/observation pipeline.

Hindsight requires its own dependency lock: Mem0 2.0.18 constrains Protobuf to
below 7, while Hindsight 0.9.0 requires Protobuf 7.35.1 or newer. The unified
lock correctly rejected the combination, so the one-system-per-image contract
isolates Hindsight rather than weakening either package. Source-context
materialization also found a committed absolute `node_modules` symlink into an
upstream contributor's `/Users/...` tree. The exact unsafe path is excluded and
recorded in the context receipt; the source archive hash remains unchanged.

An initial execution also found that reranker value `none` is rejected by the
0.9.0 runtime despite configuration guidance. The diagnostic uses the
source-defined `RRFPassthroughCrossEncoder`. Hindsight's final score also
changes slightly with wall-clock recency. The A/A gate therefore requires
identical ordered evidence plus score drift at most `1e-5`, rather than
pretending the score is byte-deterministic.

On archive task `memory-000001`, both estimands, both arms, and all repeats
passed. Candidate-present cells used 33 embedding inputs, storage holdout used
32, and served evidence contained four source-attributed records at 234
estimated tokens. First-selection isolated latency was 30.1–33.8 seconds.
Ordered records and rankings matched exactly; maximum score drift was below
`1.94e-7`. Every database, daemon, profile, log, and lock created by the passing
cells was stopped or erased. The passing artifact internally hashes to
`6898f0e75c0da7ec6077217b283d78c2ed1dc19e0fb196c9bbac6489fedbde22`;
file SHA-256 is
`095c7e8d198ca82cf4f849f1133e9f4a142f292aca24bbc7a582045f0fea2fd0`.
The source-context receipt is
`79198b53a79bd59d1813e47f74e6a5a1cc3aa468d1c1f4af936750ae12906751`.

## Matched scientific experiment

The registered contract is `experiments/memory/stage2-oss-baselines.yaml`.
Primary matching fixes:

- Qwen3.5 4B as the common OpenAI-compatible memory-construction model wherever
  the native API permits it;
- pinned `BAAI/bge-small-en-v1.5` revision
  `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a` as the common embedding model;
- reranking disabled in the primary cell;
- active `K=4`, one archive read, top-k four, and at most 256 injected tokens;
- all serialized state, graph metadata, construction calls, embedding calls,
  LLM calls, and latency charged; and
- native-default configurations reported only as separate diagnostics.

Every system must also pass update/delete behavior, cross-session isolation,
purge, A/A replay, source-attribution, prompt-injection, PII, stale-permission,
and delayed-activation tests. Graphiti receives no free graph bytes; Hindsight
reflect calls receive no free model budget.

## Actor scale is a registered axis

Memory outputs and assignments are frozen before actor comparison. The ladder is:

1. Qwen3 0.6B for interface only;
2. Qwen3.5 4B and 9B for discovery;
3. Qwen3.6 35B-A3B and GPT-OSS 120B for large-open confirmation;
4. GPT-5.6 Sol, Claude Opus 5, Gemini 3.5 Flash, DeepSeek V4 Pro, and Kimi K2.6
   for frontier confirmation; and
5. Kimi Linear 48B-A3B Base only as a separate architecture diagnostic after
   custom-code review.

This can identify a categorical model-by-memory-policy interaction. Parameter
count is not a causal scale variable because post-training, MoE active
parameters, sequence architecture, provider serving, and context length differ.

Native construction is executed once per task/arm before this actor wave.
`freeze_memory_system_outputs.py` seals every versioned request and native
selection into a content-addressed bundle. `FrozenMemorySystem` validates the
bundle, upstream receipt, request hashes, task source, budget, and estimand,
then serves that exact evidence to every actor. The provider preflight and every
self-hosted model report bind the bundle digest. Slurm additionally verifies the
file digest and mounts it read-only. Recomputing native selections separately
for different actor models is forbidden because it would confound construction
drift with model scale.

An eight-task, both-estimand reference artifact passed all request replays with
16 unique selections. Its internal bundle digest is
`0f257c61c2d3f2894b44d3af62bff8933c748feaf44acae05ca2d4bf192c391f` and
file SHA-256 is
`c29641d31914cd3548bfb912eb41a2748b03f1943fe5b92c501a5e44a553906f`.
It validates transport only; it is not memory-quality or actor evidence.

## Docker, Slurm, and remaining gates

The sidecar Dockerfiles derive from a CoTCodec research base and are intended
to copy only reviewed source archives whose hashes match source preflight. The
combined main lock fixes adapter dependencies; reviewed native source is
installed locally with `--no-deps` where supported, preventing a silent PyPI
code substitution. Publication handshake requires retained source archive,
SBOM, OCI digest, dependency lock, native-source, and embedding/construction
model receipts.

The dedicated H100 host now has working single-node Slurm and a contained
Docker discovery runtime. It maps the exact H100 allocation, disables network,
uses a read-only root filesystem, drops capabilities, and seals system,
allocation, container, command, checkpoint, and termination receipts. SmolVM
CUDA failed its kernel doctor and remains rejected on this host. This runtime
has executed actor discovery but not the native sidecars, and its old Slurm
configuration is discovery-only rather than publication isolation.
